# Следующий запуск: standard8 market-v4 (подготовлен, не запущен)

## Цель

Проверить устойчивость ML к рынку и соперникам, а не просто увеличить модель.
Архитектура остаётся pairwise HGB + value regressors, параметры заранее фиксированы.
Никакого автоматического продвижения champion или обновления Docker.

## Что изменено

- 480 эпизодов, 10 команд, 13 раундов, 8 кандидатов, 3 rollout, 8 workers.
- Четыре рынка: conservative, ESPN draft, league-rater с fallback, synthetic category Z.
- Два фиксированных типа соперников: `human` означает только простые ROTO/ADP-боты (не реальные люди); `heuristic_mixed` добавляет legacy, фиксированный punt и адаптивную эвристику **без ML**. Оценка новой и предыдущей ML идёт против одного поля, не меняющегося вместе с проверяемым checkpoint.
- 60 эпизодов на комбинацию рынка/соперников, по 6 с каждой позиции драфта. Поведение героя больше не закреплено за конкретной позицией.
- Кандидаты чередуются из списка рынка и списка силы; прежний market-prefix заполнял shortlist до попадания value-альтернатив.
- Фактический выбор behavior policy всегда включается в shortlist. ROTO/ADP/legacy больше не могут быть молча подменены reward-optimal кандидатом в обучающих метках.
- Бонус гибкости считается после добавления каждого кандидата, а не один раз для всего состояния.
- Feature contract v2 различает источник рыночного ранга: conservative, ESPN draft, league Player Rater, fallback и synthetic category Z.
- Вес value/pairwise policy в live-reranker выбирается по минимальному regret на validation из заранее заданной сетки; test при настройке не используется.
- Контрфактические ветки изолированы глубоким копированием; изменения scoring-аннотаций не переносятся между кандидатами. Шум GP/stats отличается между эпизодами, но остаётся парным для сравниваемых кандидатов внутри эпизода.
- Отдельный experiment_id и новые seeds: generation 2609042, train 260904, benchmark 2609407.
- Исправлен retry HTTP 429/502/503/504; постоянные ошибки вроде 401 не повторяются.

## Данные и пределы проверки

По умолчанию используется свежий `standard8-market-v4-inputs.json`: 300 игроков, 271 с league Player Rater и точные roster settings. На 05.09.2026 ESPN ещё не отдаёт новые projected stats: все 300 игроков используют `previous_season`. Поэтому запуск проверяет структурную способность ML выбирать пики, но **не точность нового сезона**. Checkpoint получает флаг `projection_fallback_only`, и команда promotion технически отклонит его. После появления ESPN projections потребуется новый snapshot и новый dataset/checkpoint. ESPN Player Rater bucket по-прежнему не подтверждён по периоду пользовательского скриншота.

Максимум 49 920 примеров. Стратифицированное разделение 480 эпизодов: train 384, validation 48, test 48. В каждом из восьми сочетаний рынок/соперники ровно 48/6/6 эпизодов. Test не используется для подбора параметров. Старые датасеты не объединяются с новым.

Python runner принимает `--holdout-snapshot <path>` для отдельного сохранённого снимка. Проверяет формат, размеры лиги и отличие содержимого от обучающего файла. Отличный файл сам по себе ещё не доказывает независимый сезон: происхождение требует ручной проверки. При его добавлении будет второй комплект benchmark и увеличится время. Автоматической загрузки неизвестных исторических данных нет.

## Этапы

1. Генерация нового датасета с поэпизодным сохранением.
2. Обучение одного checkpoint с фиксированными параметрами.
3. Отчёты validation и test.
4. Для каждого из 4 рынков × 2 полей соперников: 100 парных сценариев для новой ML и 100 для предыдущей v3. Каждый отчёт содержит также эвристику, ROTO и legacy-стратегии.
5. Сводка парной разницы new-vs-previous и new-vs-heuristic. Только ручное решение; не выбирать лучший рынок постфактум как доказательство общего превосходства.

Без дополнительного holdout всего 20 стадий subprocess и итоговая сводка: 16 benchmark-отчётов, 8 000 полных benchmark-драфтов (16 × 100 × 5 стратегий).

## Время

Основание: реальный запуск v3 04.09.2026 на этом компьютере. Генерация 240 эпизодов заняла 236 мин 48 с, четыре benchmark — 27 мин 31 с, train/test — менее минуты.

- Линейная оценка генерации 480 эпизодов: 7.89 часа.
- 16 benchmark при прежней скорости: 1.83 часа.
- На обучение/test заложено 10 минут.
- Итого линейно: **9.9 часа**, рабочий ориентир **10–14 часов**, разумный резерв **16 часов**.

Это экстраполяция, не измерение v4. Новые кандидаты, изоляция веток, состав соперников и параллельная нагрузка могут менять скорость. Дополнительный holdout удваивает benchmark; ориентир runner для такого варианта 12–18 часов. Масштабирование числа workers линейно лишь в формуле, на практике не гарантировано.

# Итог standard8-market-v3 и влияние коммита 8ab0854

## Решение

Не продвигать ML в live: устойчивого превосходства над адаптивной эвристикой нет. Завершены все 240 эпизодов, обучение, test и четыре benchmark. Запуск занял около 4 ч 25 мин (04.09.2026, 10:13–14:39 МСК).

На текущем консервативном рынке средние выигранные категории из 8:

- рейтинг рынка: 5.329;
- старая balanced: 4.261;
- старая фиксированная REB + BLK: 4.497;
- адаптивная эвристика без ML: 5.663;
- ML: 5.564.

Парная разница ML минус эвристика, по 100 сценариев на рынок:

- conservative: −0.099; 95% CI [−0.216; +0.018];
- espn_draft: +0.092; CI [−0.020; +0.204];
- league_rater: −0.118; CI [−0.244; +0.008];
- category_z: +0.370; CI [+0.263; +0.477].

Первые три интервала включают ноль. Значимый внутри симулятора выигрыш на синтетическом category_z не доказывает реальное преимущество. На league_rater простой рейтинг также набрал 5.193 против 5.169 у эвристики: универсальное превосходство над ROTO не установлено. Здесь категории — сезонные объёмы stats × GP, усреднённые против соперников, не шанс выиграть лигу. ESPN rater относится к default bucket, не подтверждённому периоду пользовательского скриншота.

## Влияние на обучение

- Венгерский solver ускоряет дневные составы сезонной аналитики. Self-play использует собственные позиционные проверки и сезонный evaluator, не optimize_daily_lineup. Заявленное ускорение 117× относится к синтетическому микрозамеру, не к ML.
- Исправление TO относится к общему comparator; в standard8 TO нет, драфтовый evaluator отдельный.
- Большинство категорий в сезонном Punt Analyzer не меняет draft_strategy/метки self-play.
- can_play_slot поддерживает составные названия слотов. На замороженных 300 игроках и 13 слотах все 3 900 результатов совпали с прежней реализацией.
- Guard champion теперь проверяет точный набор категорий для автоматического выбора. Явный DRAFT_MODEL_CHECKPOINT по-прежнему обходит этот автоматический выбор; его формат нужно контролировать отдельно.
- UI-очередь, виртуальные пики, фоновые benchmark, snapshot-cache, авторизация и persistence полезны для эксплуатации, но не обучают модель и не меняют сохранённые признаки.

Повторная оценка checkpoint после merge дала точно те же test-метрики. Дополнительно повторён первый сценарий каждого из четырёх рынков, по пять стратегий: все 20 пар category_wins/league_rank точно совпали с сохранёнными результатами. Это выборочная проверка, не повтор всех 2 000 драфтов benchmark. Причины пересоздавать датасет только из-за этого коммита не обнаружено.

## Найденные интеграционные ограничения

1. После обновления get_league_meta бросает HTTPException(503), а CLI _draft_inputs ловит только ConnectionError/OSError/AttributeError. Без готового snapshot начальный сбой ESPN обойдёт четырёхкратный retry. Воспроизведено на mock: attempts=4, фактически один вызов и выход с HTTPException. Текущий завершённый запуск и повторная оценка на его snapshot не затронуты. Это следует согласовать до следующего сбора данных.
2. Docker теперь монтирует ML-artifacts, но Dockerfile.backend по-прежнему устанавливает requirements.txt без scikit-learn/joblib из requirements-ml.txt. Один volume не делает ML inference готовым к запуску.
3. Изменились пути SQLite на .cache. Перед пересозданием контейнера нужно сохранить и перенести старые журналы. В этой задаче контейнеры не пересоздавались, ML не продвигалась.

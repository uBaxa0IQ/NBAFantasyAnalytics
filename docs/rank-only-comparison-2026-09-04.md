# Отказ от ADP: сравнение без ML

## Решение

Безусловная миграция всего приложения на Player Rater не обоснована: польза зависит от поведения соперников. Live и подготовленный training runner не переведены на rank-only. Обучение не запускалось. Добавлены только воспроизводимый эксперимент и необязательные отдельные представления рынка для героя в benchmark.

## Дизайн

Один замороженный снимок standard8, 300 игроков, 10 команд, 13 раундов. В каждом мире 10 позиций × 5 прогонов = 50 парных сценариев. Три представления рынка нашего пикера × четыре мира = 600 полных драфтов. Во всех случаях герой использует adaptive_heuristic, ML явно отключена.

Внутри пары неизменны соперники, их рейтинги, seed, статистика, evaluator и слоты. Меняется только информация о рынке, доступная герою. Пики соперников, естественно, зависят от того, кто остался после действий героя. Оценщик — сезонные stats × GP, средние выигранные категории против остальных команд; не недельный H2H и не вероятность чемпионства.

Представления героя:

- current: текущая консервативная смесь двух рейтингов с ADP;
- no_adp_boards: более ранний из двух рейтингов, без смешивания с ADP;
- league_rank_only: только совместимый с категориями ESPN Player Rater. При отсутствии — собственный category-Z rank, явно не ESPN. Для этого режима и ADP, и общий draft rank удалены из входов героя.

Миры соперников: половина простых ROTO/ADP-ботов (current_mixed), только рейтинг лиги, только общий draft rank, только ADP. Это гипотезы о поведении людей, не восстановленные реальные лиги. Как и в текущем benchmark, прямые rank-боты выбирают первым ключом ранг; seed меняет рыночные оценки героя и оценочный шум, но не создаёт эмпирическую модель случайных человеческих пиков.

## Чистый рейтинг лиги против текущей смеси

- Смешанные ROTO/ADP-соперники: 5.511 → 5.469 категории; Δ −0.042, 95% CI [−0.178; +0.094]. Преимущество не установлено.
- Соперники по рейтингу лиги: 4.167 → 4.744; Δ +0.578, CI [+0.328; +0.827]. Выигрыш внутри этого сценария.
- Соперники по общему draft rank: 6.178 → 6.040; Δ −0.138, CI [−0.216; −0.059]. Ухудшение внутри этого сценария.
- Соперники по ADP: 6.329 → 6.202; Δ −0.127, CI [−0.231; −0.022]. Ухудшение внутри этого сценария.

## Просто убрать ADP, сохранив оба рейтинга

Относительно current: смешанное поле −0.051 [−0.155; +0.053], league rank +0.089 [−0.080; +0.257], draft rank −0.113 [−0.181; −0.046], ADP −0.002 [−0.081; +0.077]. Устойчивого выигрыша нет. Значит, преимущество league_rank_only в соответствующем мире — не просто следствие удаления ADP, а согласования нашего представления рынка с соперниками.

## Ограничения

- Это 8-кэт, не проверка нестандартной 11-кэт.
- 35 из 300 игроков не имеют совместимого Player Rater и используют synthetic fallback. Строго «100% официальный рейтинг ESPN» этим тестом не проверен.
- Период ratings.0 API не подтверждён по пользовательскому интерфейсу. Рейтинг Янниса 185 против draft rank 15/ADP 5.12 иллюстрирует сильное расхождение источников.
- Проверена прямая замена источника в существующей эвристике доступности. Не доказано, что специально обученная/калиброванная rank-based модель поведения не смогла бы работать лучше.
- Интервалы приближённые парные интервалы текущего evaluator, не реальные гарантии. Один снимок, ограниченное поле ботов; усреднять миры с произвольными весами и объявлять общий выигрыш нельзя.

## Что затронула бы миграция

ADP используется в прогнозе доступности и lookahead, «брать/ждать», рыночной цене/переплате, отображении состава, стратегиях ботов и ML market-features. В сезонных расчётах сила игроков уже оценивается по категориям, а не ADP. Ранг не заменяет точные статистические вклады, объёмы попыток, панты и совместимость состава — эти расчёты нужно сохранить.

Предпочтительный следующий шаг при подтверждении пользователем: отдельный источник рынка на уровне конкретной лиги, включая режим без ADP; зафиксировать период/источник Player Rater и отдельно обозначать отсутствующие рейтинги. Не выдавать это за универсально лучшую настройку и не удалять альтернативные сценарии проверки.

Артефакт: `artifacts/draft_ml/rank-only-comparison.json`, включая все 200 парных сценариев и составы трёх политик. Воспроизведение: `python scripts/compare_rank_only.py --execute --output <новый-путь.json>`; без --execute только план. Проверки проекта: 123 pytest tests passed.

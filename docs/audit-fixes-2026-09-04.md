# Изменения по результатам аудита

## Расчёты

- Исправлено направление TO и поддержаны переданные обратные категории в общем comparator.
- Сезонный движок читает активные слоты ESPN, поддерживает составные позиции и исключает bench/IR из активных мест.
- Экспоненциальный DP заменён точным венгерским алгоритмом назначения. Режим заполнения сохранён для нейтральной проекции; matchup-utility позволяет оставить место пустым.
- Повторяющиеся дневные наборы игроков переиспользуются; добавлен ограниченный кэш снимков на 30 секунд.
- Punt Analyzer использует большинство фактических категорий; нельзя выбрать комбинацию, оставляющую меньше необходимого для победы.
- Текущая неделя в сезонном прогнозе объединяет фактическую статистику и ещё не начавшиеся игры с пересчётом процентов из попаданий/попыток.
- Учтена дата ожидаемого возвращения ESPN для игроков вне IR. Неизвестные возвращения не выдумываются.

## Рекомендации и обмены

- Календарные замены ранжируются по предельному вкладу в категории против соперника, затем по Z и числу игр, вместо безусловного приоритета числа игр.
- Проверяется весь загруженный пул доступных кандидатов. Защищены травмированные игроки и верхняя половина состава по сезонным данным; показываются только положительные замены.
- При завершении календаря нет рекомендаций по прошедшей неделе.
- Оптимизатор оставшихся дней использует тот же принцип вклада в категории соперника.
- Ручной выбор состава сохраняется до/после обмена; игроки заменяются по составу сделки, соблюдается лимит Top-N.
- Добавлена проверка принадлежности отдаваемых игроков и дубликатов. Календарный горизонт сделки явно указан.
- Расчёт Z свободных агентов в карточках использует общее ядро; свободные агенты включены в массовые тренды.

## Интерфейс и драфт

- Добавлены редактируемая очередь и виртуальный ростер, сохранение по лиге/сезону/команде, пересчёт после виртуального выбора и перенос очереди в live.
- Исправлен ключ кэша рекомендаций: учитываются лига и виртуальные пики.
- Добавлен переход между сезонной аналитикой и драфтом.
- Исправлено чтение/запись React-ref во время рендера.
- Проценты стратегии и уверенности подписаны как оценки модели/доли симуляций; уточнены подписи истории рангов, трендов и прогнозов.
- Тяжёлые benchmark запускаются фоновыми ограниченными задачами с дедупликацией; frontend опрашивает статус, прекращая опрос при смене контекста.
- Основные экраны загружаются отдельными JS-частями.

## Надёжность и проверяемость

- Начальный сбой ESPN возвращает 503 и не кэшируется. При ошибке обновления восстанавливается прежнее состояние, показывается признак устаревших данных.
- Сетевой refresh вынесен из event loop, параллельные refresh сериализованы.
- Docker сохраняет журналы SQLite, настройки и ML-артефакты на хосте.
- Добавлен необязательный серверный NBA_API_TOKEN и экран входа; без настройки токена остаётся локальный режим без авторизации.
- Исключено автоматическое применение standard8 champion к другим наборам категорий.
- Коэффициенты статистики отклоняют NaN/Infinity и значения вне 0–1.
- Добавлено сохранение будущих прогнозов до начала матчапа и endpoint проверки по завершённым неделям.

## Проверки

- Итоговый полный прогон: **94 passed**, 47.54 секунды. ESLint: **0 ошибок, 0 предупреждений**. Production build Vite: успешно, без предупреждения о крупных chunks. Импорт приложения: 50 API-маршрутов.
- Регрессионные тесты проверяют TO, слоты, brute-force-эквивалентность назначения, 8-cat punt, ручные ростеры, процентные категории, начавшиеся игры, возврат после травмы, сбой ESPN, add/drop, доступ, фоновые задачи и фиксацию прогнозов.
- Browser smoke на синтетическом ESPN fixture: очередь, виртуальный состав, пересчёт, сохранение после reload, переход prep → live. Ошибок страницы нет. Это не проверка живой сессии ESPN.
- Дополнительно в браузере проверены экран входа, сохранение ключа в sessionStorage и загрузка приложения после авторизации. Временные тестовые серверы остановлены.
- Синтетический замер 13 игроков / 10 слотов: исходный DP 92.372 мс, новый solver 0.792 мс на вызов; одинаково 10 стартеров и ценность 7.5. Ускорение около 117× в этом примере, не гарантия такого же ускорения API.

## Ограничения, которые нельзя устранить одной правкой

- Реальная точность рекомендаций и превосходство ML требуют будущих фактических результатов. Добавлен сбор данных; подтверждённого процента успеха пока нет.
- Рекомендации моделируют одиночную замену и эвристическую ценность категорий, не точную вероятность победы и не глобальную цепочку waiver-транзакций.
- Неизвестные травмы, изменения ролей, будущие обмены и точные будущие ESPN tie-breakers не предсказываются. Сезонная таблица остаётся явно обозначенным сценарием.
- NBA_API_TOKEN нужно задать при размещении в интернете; полноценные пользовательские роли не добавлены. Перед пересозданием существующего Docker-контейнера нужны перенос/backup прежних SQLite-файлов — приложение не развёртывалось в ходе этой работы.
